# Features

## Polyhedra

- 35 fixed seed types: 5 Platonic, all 4 regular non-convex Kepler-Poinsot, 13 Archimedean, and 13 Catalan solids. The Kepler-Poinsot category follows Families and shows each conventional Conway form; its embedded physical meshes resolve classical face intersections for rendering and export. A Families category immediately after Platonic adds Prism, Antiprism, Pyramid, and Bipyramid for every `n` from 3 to 100. Popup rows show family names without a number; the initially remembered size is 3. The selected seed displays its concrete `n`, and adjacent up/down controls change it within the bounds. Both popup selection and left/right seed navigation reuse the last family `n` across family and fixed-seed changes, including while transforms are present. Deleting transforms retains it; resetting from a seed-only state clears it back to 3.
- Transform chains containing the primitive Truncated, Rectified, Dual, Snub, Propeller, Whirl, Quinto, Chamfered, `Canonical` (the canonicalization operation), Greatened, Stellated, and topology-dependent orbit-targeted operations. Greatened and Stellated construct supported regular-star forms and reject inputs outside their exact regular domain. None removes an existing stage. The transform popup lists fixed primitives under Transform, combinations under Macro, and available orbit-targeted operations under a final section in the global order Drop face, Drop edge, Drop vertex, Kis face, Truncate vertex, Rectify vertex.
- Kis face is offered for inputs with multiple face orbits and replaces every face in one selected orbit with pyramidal triangles. Truncate vertex and Rectify vertex are offered for inputs with multiple vertex orbits; they cut one orbit at the regular truncation depth or at shared edge midpoints. Applying any selective operation to all corresponding orbits produces exactly the same geometry as its full Kis, Truncated, or Rectified counterpart.
- A newly added orbit-targeted operation selects its first valid orbit unless the UI has remembered a supported orbit of the same element kind. The selected target is displayed concretely, such as `Kis α` or `Truncate A`. While it is the last chain item, compact up/down controls to its right cycle and wrap through the currently valid orbits. The last face, edge, and vertex targets are retained separately, so changing operation type through the popup or left/right controls reuses the corresponding orbit; for example, Truncate B changes to Rectify B.
- Conway-style macros for Kis (Dual → Truncated → Dual), Join (Dual → Rectified → Dual), Needle (Truncated → Dual), Zip (Dual → Truncated), Cantellated (Rectified → Rectified), Bevelled (Rectified → Truncated, conventionally `ta`), Ortho (Dual → Rectified → Rectified → Dual), Meta (Dual → Rectified → Truncated → Dual), and Gyro (Dual → Snub → Dual). Macros are stored as one chain item but execute as their primitive sequence in the Wasm core.
- When last in the chain, Truncated, Kis, Cantellated, Bevelled, Snub, Chamfered, their parameterizable macros, and the applicable Kis/Truncate/Rectify orbit operations expose a gear immediately after the pill name. Earlier transforms remain compact and cannot open a settings popup. The sliders vary normalized depth, distance, height, width, inset, or twist around the regular `100%` construction. A reset action in the popup's lower-right corner restores every parameter to `100%` and restores standard chirality. The worker derives each slider's safe interval from the mesh entering that exact transform stage and the currently selected values of its other controls; values outside it cannot be selected, and a manually serialized unsafe value produces an invalid-geometry warning instead of a broken render. Changes are returned with topology-compatible interpolation keyframes. URL tags append only non-default values, such as `t~d=0.7`; defaults retain all existing compact tags. Full Rectified and Join remain fixed because their shared edge midpoint has no continuous symmetric displacement that retains rectified topology.
- Snub, Propeller, Whirl, Gyro, and the four chiral seed types have a prime-tagged alternate handedness. For a last-chain chiral transform, the flip button lives inside its settings popup; chiral seeds retain their pill control. Flipped names and URL operation tags end in `'`, before any continuous parameter suffix. Quinto is achiral and has no flip control.
- Optional prefix simplification: macros are expanded and adjacent Dual pairs are cancelled when comparing the applied end of the chain with every single primitive or macro. The longest formally replaceable prefix, including its chirality, receives an inline suggestion. Nothing changes until it is clicked; acceptance may expose the regular `aa`/`at` composition kernel and change the coordinate realization while preserving the Conway operation.
- Composition-aware regular geometry for consecutive Rectified + Rectified and Rectified + Truncated operations. These pairs use the fused cantellation and bevel geometry kernels, so their expanded and macro forms are identical without iterative canonicalization.
- Optional catalog replacement: when a completed transform chain at regular settings or an untransformed family member is orientation-preservingly equivalent to a fixed seed, a suggestion for the proper catalog representation appears to the right of the chain. Examples include Prism 4 → Cube, Antiprism 3 → Octahedron, Pyramid 3 → Tetrahedron, and Bipyramid 4 → Octahedron. Moving a continuous setting away from its default clears the suggestion without running recognition; resetting the chain to regular settings reruns recognition and restores any valid suggestion. The current exploratory state remains unchanged until the suggestion is clicked.
- Background WasmGC execution for manipulation algorithms, with live per-stage convergence progress attached to the transform pill currently consuming CPU and cancellation when a newer state supersedes it. Each operation gets a 500 ms grace period, measured from its first post-load worker progress event, so short recalculations never flash a progress pill. The central loading status represents only Wasm module loading and disappears before transform progress begins.
- Circumradius, midradius, or inradius normalization.
- Transform applicability, identity, maximum-size, failure, and non-planar-face feedback.

## Exploration and rendering

- Interactive WebGL face and edge rendering with mouse and touch rotation and zoom.
- Two-way orbit rollover between the F/E/V popup rows and the canvas. Canvas picking considers front-facing geometry; manually hidden face orbits retain their full virtual picking surfaces. Selected faces are highlighted, selected edges receive a contrasting overlay, and selected vertices are marked with small shaded balls.
- Configurable automatic rotation, view scale, face expansion, transparency, width, rim, display mode, scene environment, and symmetry plane/axis size. The default `Table` environment places the rotating polyhedron above a fixed neutral-gray rough-plastic plane and casts one sharp geometry-accurate shadow from the animated face mesh; `None` preserves the background-only view. One fixed studio light illuminates the polyhedron in both modes and projects the table shadow, so toggling the environment never changes the polyhedron's illumination. Face and table shading use a linear-light, energy-conserving dielectric Cook-Torrance BRDF with GGX roughness, correlated Smith visibility, Schlick Fresnel, the shared studio key, and a constant-environment fill. The compact material controls expose only Key light, Fill light, Roughness, and IOR; defaults model moderately glossy PLA with roughness `0.45` and IOR `1.46`.
- Configuration sliders, checkboxes, and dropdowns stay synchronized in both directions with programmatic and URL-driven parameter changes.
- Global [keyboard navigation](keyboard.md) mirrors the visible controls: arrow keys change the last transform or seed, navigate the Add, F/E/V, and Saves popup rows, and adjust any displayed family/orbit target; Enter activates the highlighted Add or Saves row or accepts a shown replacement, `+` toggles Add, Delete or Backspace deletes the last transform or resets the seed, and Escape closes the open popup. `Space` toggles the highlighted face orbit in the Faces popup and all face orbits elsewhere; `F`, `E`, `V`, `Y`, and `R` control inspection popups, symmetry, and automatic rotation. `C`, `X`, `S`, and `?` toggle configuration, export, saved configurations, and keyboard help. Shortcuts are suppressed while an input, slider, dropdown, text area, or editable field has focus, except that Escape remains available for dismissal. A `?` button below Save opens a grouped shortcut reference that also identifies the running application version.
- Smooth geometry transitions and topology-aware keyframe animations returned by the Wasm core. Parameterized primitives use collapsed or limiting topology, Propeller/Whirl/Quinto expand from exact planar subdivisions, and every component of a multi-part macro advances together on one shared 0–100% clock. A fused final-topology mesh collapses its component-created vertices onto the input at 0% and reaches the exact macro result at 100%, so applying or removing a macro occupies one configured operation duration. Replacing unrelated operations gives both the old-out and new-in phases the configured duration; compatible pairs use one direct morph, while identity operations are normalized away before macro keyframes are built and stationary stages are omitted. Selective Truncate vertex and Rectify vertex use cut-depth kernels; changing target orbit animates the old target out before the new target in, while switching operation on one remembered orbit uses a direct cut-depth transition. Drop, selective Kis insertion/removal or retargeting, and chirality flips are intentionally immediate because they have no stable non-self-intersecting mesh correspondence; selective Kis Height changes still interpolate directly.
- Greatened and Stellated changes are immediate: resolving classical face intersections changes physical cell topology, and no connected non-self-intersecting collapsed keyframe exists. Continuous or selective Kis is likewise unavailable on resolved regular-star surfaces, although default full Kis remains usable when its result is proper.
- Rotation-orbit classification with orbit-based coloring and selection highlighting. Bottom F/E/V labels append the actual geometric orbit count only when it exceeds one, such as `F: 38/3`, while one-orbit labels remain compact.
- A separate bottom symmetry pill reports the full Schoenflies point group, such as `C_nv`, `D_nh`, `T_d`, `O_h`, or chiral `I`, with its fold and suffix rendered as an HTML subscript and its full name in a tooltip. The same toggle draws every distinct proper-rotation axis as a thin black line and every reflection plane as a translucent circular disk; chiral geometries retain the axis overlay and explicitly report that they have no reflection planes. Config sliders scale plane radii and axis half-lengths from `1.0` to `2.0` times the circumradius, defaulting to `1.1` and `1.2` respectively. Overlay visibility and non-default sizes are encoded in the URL.
- Live face/edge/vertex counts. A standalone GitHub logo anchors the lower-right corner to the same grid as the bottom controls and right-side buttons and opens the project repository in a new tab. Its centered small caption reports live frames per second while the canvas is drawing and reads `Open Source` while idle.
- The export drawer has an optional print preview that replaces face-orbit colors with one PLA material color and suppresses rendered edges for an unobstructed surface preview, while retaining the live plastic lighting, geometry, and environment. It defaults to red. An in-place picker provides Basic colors plus a perceptual OKLCH hue wheel and Hue, Chroma, and Lightness sliders; opening the picker enables preview so every choice is visible immediately.

## Inspection

- Face-kind table with count, inradius, adjacency, vertex figure, planarity, visibility, and available Drop/Kis actions.
- Edge-kind table with count, midradius, local geometry, and available Drop action. Each row includes a color-coded planar net of its two adjacent faces: the named left face is placed left of a centered vertical shared edge and the named right face is placed on the right.
- Vertex-kind table with count, circumradius, adjacency, vertex figure, and available Drop/Truncate/Rectify actions.
- Every F/E/V orbit row places all currently available targeted actions at its right edge in the same global order as the transform popup. The ×, upward-caret, scissors, and compress icons mean Drop, Kis face, Truncate vertex, and Rectify vertex; each icon has a tooltip naming its exact operation and target orbit.
- Hide/show all faces or individual face kinds with immediately synchronized controls, while retaining configurable rims and shell width. The three-state all-orbit control (all visible, mixed, or all hidden) is available both in the face table header and as a discoverable circular button beside the bottom F/E/V control; both copies expose the same state-aware tooltip and action.

## Persistence and export

- Complete application state, including non-default continuous transform parameters and print-preview color, is encoded in the URL hash and restored on load. Disabled default-red preview remains implicit.
- A save/load button below Export opens an append-only local save log. Save uses the current catalog-derived polyhedron name immediately, while the editable field selects a custom name and Enter is equivalent to clicking Save. Every entry stores the exact compact URL state, a cropped rendering preview, and its timestamp. Entries remain in browser local storage, are shown newest first with relative ages, and load by restoring the saved URL state. There is intentionally no delete action.
- Export of convex, concave, non-planar, and resolved regular-star solid geometry to standards-compatible watertight ASCII STL without zero-area facets, including hidden-orbit rims.
- Export of the same shared triangulated geometry to OpenSCAD source.
- Export size and shell parameters are controlled from the export drawer.

## Runtime requirements

The application requires ES modules, WebGL, and WasmGC. Current Chromium, Firefox, and Safari releases that implement Kotlin/WasmGC are supported; legacy browsers without WasmGC are not given a JavaScript algorithm fallback.
